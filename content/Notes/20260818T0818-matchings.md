# matchings

Given two disjoint sets $S$ and $H$, a matching in $\left( S, H \right)$ is a collection of disjoint pairs $M \subseteq S \times H$.

This models assignment of medical students to hospitale, pilots to planes, users to servers, etc. It basically means an assignment from one set to the other. A matching is _perfect_, if it covers $H$ and $S$.

## Preferences

A preference on $H$ is an ordering of elements $H$, i.e. an ordered list.

Assume every student and every hospital has a list of preferences, e.g. $>s_{1}: h_{1} > h_{2} > h_{3}$, $>h_{1}: s_{2} > s_{1} > s_{3}$.

## Instability

Definition: Given a matching $M$, $s \in S$, $h \in H$ is an _unstable pair_ if ${s, h} \notin M$, but $\left\{ s, h' \right\}$, $\left\{ s', h \right\} \in M$ and $h >_{s} h'$, $s >_{h} s'$. That is to say, both $s$ and $h$ prefer each other over their current matches.

A perfect matching $M$ is _stable_ if there is no unstable pair. An unstable pair requires both parties to prefer another item. The naive way to check this would be to check for each matching if all the other options of $h$ for each $s$ are unstable. If none of these are unstable, the matching itself is stable.

## Stable matching problem

> [!NOTE] Problem: Stable Matching
> Given sets $S$ and $H$ with preference lists,
> Return find a stable matching $M$.

- Is there always a solution?
- How quickly can we find it?

Brute force algorithm:

```
input: S, H, preference lists

for every assignment M between S and H:
    if M is stable:
        return M
return None
```

```
for i_1 \in { h_1, h_2, \dots }:
    for i_2 \in { h_1, h_2, \dots } excluding { i_1 }:
        for i_3 \in {h_1, h_2, \dots } excluding { i_1, i_2 }:
            etc. etc - n times
```

This algorithm is by definition correct, although is is very inefficient.

Given that both $S$ and $H$ are of size $n$ (this is a prerequisite for a stable matching to exist), the time complexity would be $O \left( n^{n} \right)$, however because we ignore the already chosen $h$ (because one node can not be chosen multiple times), it is instead $n!$. This has to be done for each $n$, with a final time complexity $O \left( n! \cdot n \right)$ where $n = \left| S \right| = \left| H \right|$.

### Gale-Shapley algorithm

Theorem (Gale, Shapley; 1962): There exists an $O \left( n^{2} \right)$-time algorithm for the Stable Matching problem. It always outputs a stable matching.

> [!NOTE]
> It wouldn't really be feasible to solve this in less than $n^{2}$ because the input will be of size $n^{2}$ with the preference lists, so anything faster would be unviable.

> [!NOTE]
> They received the Nobel Prize in Economics for stable matching theory and G-S algorithm :o

> The algorithm was originally used to match medical students to hospitals in the US. Before this algorithm was applied in 1952, the naive version would tak every long, and hospitals had to make offers up to 2 years before admission. The method was further updated in 1998 to account for other constraints.

A modern application of this is content delivery networks. Users and servers have preferences based on latency, loss rates, etc. In this case, we need to quickly compute a good matching.
